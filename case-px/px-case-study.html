現場轉換阻力

對照舊有「外部拉新」路徑與全新「盤活老客」路徑之結構摩擦力對比。

質性痛點：系統無法辨識既有會員，將「身分證已註冊」之老會員視為新客，造成高達 87% 的流程摩擦流失。
新路徑：以「盤活既有老會員」為核心的無痛漏斗
01. 起點

全聯 App (已有 MID)

從內部 1300萬會員導流
02. 觸發

點擊 Banner 一點就綁

技術核心：透過 OAuth 授權機制於背景串接，直接在系統底層對齊 UID (LINE) 與 MID (PXPay)，將轉換路徑大幅精簡 60%。

答案不是加碼誘因，也不是拉新客；
而是降低 user flow 阻力，讓既有會員一鍵綁定。

PM Thinking: 最好的誘因不用花預算買，它已經在用戶的抱怨裡了。綁定從「配合行銷」變成「對用戶自己有用」。

Decision 03

不求一次到位

（MVP 漸進式交付）

限制挑戰421 上線死線臨頭，PXPay／MAAC／LINE 三方 API 串接不及。

MVP 策略拆成三階段漸進式交付，先低成本驗證方向，再投入高階技術資源。

PHASE 1
建立渠道・快速擴粉
PHASE 2 · 421 檔期
Banner 教學引導上線
低成本驗證「不重新註冊」方向
PHASE 3 · 整合期
One-Click API 背景綁定

PM Thinking: 先用低成本證明需求存在，再投資做順滑的版本。順序反過來，是拿工程資源賭一個未經質性驗證的假設。

06
Execution

How do you move people who don't have to believe you?

方向對了，還要讓一群沒有義務相信你的人一起往前跑。當時 IT 團隊正在全力推進跨集團的「超商取貨」特大號專案。我知道我無法、也不應去硬搶一線技術資源，於是我發揮技術共情能力，採取了以下行動：

技術實現：跨系統數據閉環架構

展示 PXPay、LINE 官方帳號與 MAAC 自動資料 Mapping 之後端技術拓撲。

DATA OWNER 01
全聯 App (PXPay)
Hold: MID (Member ID)

用戶在 App 內點擊 Banner 發起導流，背景帶出經過 OAuth 簽章的 MID 會員憑證。

DATA OWNER 02
LINE Official Account
Hold: LID (LINE User ID)

LINE 後台偵測用戶進入，自動回傳 LID 識別碼，透過 Webhook API 傳遞至 MAAC。

INTEGRATOR
MAAC 數據中樞
API Mapping: MID ⇄ LID

系統背景自動比對並對齊 MID 與 LID，不需用戶手動重填任何表單，秒級完成數據閉環。

01. 對 IT 展現共情

理解排程卡點，將大需求拆碎成漸進式 Redmine 工作項目，讓工程師有餘裕，不硬搶一線資源。

02. 設計溝通降維

不丟複雜死板的規格書，直接手繪情境 Wireframe 草稿，讓不具行銷背景的開發者一秒共情。

03. 對主管結果扛責

主動承諾用 Q1 實質營收與數據轉化率驗證這個方向，用客觀成果換取放手做的空間。
